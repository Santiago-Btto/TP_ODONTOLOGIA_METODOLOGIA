## Disponibilidad y entradas reales

El agente encontró el trigger «planificación o revisión de escenarios de consulta de agenda» en [el registro](../../../.atl/skill-registry.md), lo confirmó en [AGENTS.md](../../../AGENTS.md) y abrió [la skill](../../../.agents/skills/revisar-escenarios-agenda/SKILL.md). Consultó `CHANGES.md` §C-02, `knowledge-base/04_modelo_de_datos.md` §Turno, `05_reglas_de_negocio.md` §RN-DI-01/RN-DA-02, `06_funcionalidades.md` §US-002, `07_flujos_principales.md` §Flujo 1, `10_preguntas_abiertas.md`, la especificación vigente `openspec/specs/creacion-de-turnos/spec.md`, el estado de OpenSpec y las pruebas actuales. La validación estructural `py -3.13 -B C:/Users/esteb/.agents/skills/skill-creator/scripts/quick_validate.py .agents/skills/revisar-escenarios-agenda` devolvió **`Skill is valid!`** (salida 0).

La revisión se ejecutó cuando C-02 aún no tenía artefactos de propuesta completos. Por eso los estados «falta»/«ambiguo» son el **diagnóstico inicial**; las pruebas mencionadas son propuestas para la implementación posterior, no resultados ejecutados.

## Resultado de la invocación

| Regla y fuente | Escenario Dado/Cuando/Entonces | Prueba propuesta | Diagnóstico inicial |
|---|---|---|---|
| Rango obligatorio, filtro y orden; `CHANGES.md` §C-02, US-002 | Dado un día con turnos de dos profesionales, cuando se consulta con `profesional_id`, entonces aparecen sólo los turnos intersectantes de ese profesional, ordenados por inicio y con profesional y box identificados. | `test_consultar_agenda_diaria_filtra_profesional_y_ordena_por_inicio` | Falta en spec y tests. |
| Filtros por box y profesional; C-02, US-002 | Dada una semana con turnos en varios boxes, cuando se consulta sólo por box y luego por ambos filtros, entonces se restringe el resultado según la regla de combinación. | `test_consultar_agenda_semanal_filtra_box`; `test_consultar_agenda_combina_filtros` | Ambiguo: combinación aún no expresada. |
| Intervalos `[inicio, fin)`; RN-DI-01, modelo `Turno` y spec vigente | Dado `[09:00,10:00)`, cuando se consulta, entonces se incluyen turnos contenidos, que empiezan antes, terminan después o abarcan todo el rango; se excluyen los que sólo tocan un extremo. | `test_consultar_agenda_incluye_cuatro_formas_de_interseccion`; `test_consultar_agenda_excluye_turnos_contiguos` | Falta en la consulta. |
| Rango sin resultados; C-02 | Dado un rango válido sin turnos, cuando se consulta, entonces se devuelve una colección vacía. | `test_consultar_agenda_rango_sin_resultados` | Falta. |
| Intervalo válido; C-02 y RN-DA-02 como antecedente | Dado `inicio >= fin`, cuando se consulta, entonces se informa un error definido para la consulta. | `test_consultar_agenda_rechaza_rango_invalido` | Ambiguo: falta contrato de respuesta. |
| Entradas inválidas; C-02 y reglas de API existentes | Dadas fechas ausentes, mal formadas o sin zona, cuando se consulta, entonces se aplica una política explícita de validación. | Pruebas parametrizadas de entrada tras definir el contrato. | Ambiguo: formato y respuesta sin definir. |

**Aporte concreto y segunda revisión:** la matriz convirtió el alcance general de C-02 en escenarios verificables y señaló vacíos antes de iniciar la implementación. Tras escribir [proposal](../../../openspec/changes/consultar-agenda/proposal.md), [design](../../../openspec/changes/consultar-agenda/design.md), [spec](../../../openspec/changes/consultar-agenda/specs/consulta-de-agenda/spec.md) y [tasks](../../../openspec/changes/consultar-agenda/tasks.md), se volvió a aplicar la revisión de la skill: quedaron cubiertos el éxito diario/semanal, cuatro formas de intersección, ambos bordes contiguos excluidos, filtros individuales y `AND`, orden, vacío y error por `fin <= inicio`. Esa segunda pasada detectó y motivó agregar el ID de texto sin coincidencias, fecha mal formada y comparación de instantes con desplazamientos equivalentes; `fin <= inicio` quedó rotulado como error de regla de consulta con tareas de prueba de aplicación y API. `openspec status` informó los cuatro artefactos de planificación completos y `openspec validate consultar-agenda --strict` pasó. **Ninguna de esas pruebas de implementación se ejecutó**: las casillas de `tasks.md` siguen abiertas.

La skill no puede decidir por sí sola la visibilidad por rol, el tratamiento futuro de cancelaciones ni el desempate entre inicios iguales; esas cuestiones quedaron identificadas como límites o decisiones pendientes, no como hechos inventados. Para el antes/después concreto de una sugerencia inadecuada del MCP, ver [Context7: UUID frente a ID de texto](context7-uso.md#revision-de-la-propuesta-antes-y-despues).
